Repo architecture
clear module boundaries

The repository is split by product surface and runtime responsibility.

frontend/ Landing, dashboard, history, settings, and the live orchestration canvas.
backend/ HTTP surface, auth, sessions, rate limiting, websockets, and orchestration runtime.
sdk/ JavaScript and Python clients for attached agents.
skills-md/ Markdown skills that can be normalized into Flowfex capabilities.

Frontend

  • React + Vite routing
  • Zustand canvas and session state
  • Socket client bound to three namespaces

Backend

  • FlowfexServer entry surface
  • Better Auth and session services
  • Persistence and usage tracking

Orchestration

  • Intent planning and retrieval
  • Plan selection and graph building
  • Execution runner and event streaming
